# Runtipi operations

The app-store package contains a vendored `repo/` snapshot and must record canonical source commit and tree hash at release. Product code should be exported from `ianras77/web-astrology` through a repeatable checked release process. Do not deploy or restart production from this worktree without a reviewed release, backup, migration qualification, image rebuild, and endpoint/user-flow proof.
The app-store wrapper compose is part of the deployment contract. It pins Qdrant to `qdrant/qdrant:v1.12.5`, runs `prisma migrate deploy`, and passes the canonical server-side RassyMind variables. Validate it with `APP_DATA_DIR=/tmp ROOT_FOLDER_HOST=/tmp APP_STORE_ID=apps APP_HOST=localhost docker compose -f ../docker-compose.yml config` from the vendored repository's parent package directory before publishing.

Production images should use `infra/Dockerfile.api` and the parameterized `infra/Dockerfile.web`. Dependencies, Swiss Ephemeris native bindings, application compilation, and Prisma client generation happen at build time; runtime containers must not install packages or rebuild native code. The checked-in bind-mounted Compose remains for local iteration, not immutable production releases.
